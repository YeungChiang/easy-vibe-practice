# Task01 — AI时代，会说话就会编程

课程：Datawhale 第86期 Easy-Vibe · 小组：鲸语织境

截止：2026-11-18 03:00（北京时间）。

## 1. 核心知识

- 自然语言可以降低编程入门门槛，但需求是否清楚、结果是否符合预期仍需人为判断。
- 小而清晰的应用适合快速迭代。复杂系统需要任务拆分、模块协作与进一步的工程验证。
- 普通贪吃蛇是 AI 辅助开发的应用；只有游戏运行时实际调用模型，才能将诗画生成认定为真实 AI 功能。
- HTML 管结构，CSS 管样式，JavaScript 管状态和交互；服务端负责保存密钥并调用模型接口。

## 2. 实践：鲸语织境 · 诗境贪吃蛇

以课程中的贪吃蛇为原型，结合小组名称「鲸语织境」，设计一个通过收集词语生成诗画的小游戏。

按照教程的玩法，保留移动、进食、计分和碰撞结束，扩展为拾取八个词语后触发诗画生成，并提供重新生成选项。

实现分两种模式：

- 本地模拟：规则拼接诗句和程序绘制 SVG，零依赖，可离线运行；不属于真实模型生成。
- 模型接口：Node.js 服务端依次请求兼容 Chat Completions 和 Images Generations 格式的模型接口；需自行配置两个模型服务，尚未真实联调。

### 运行方式

解压或下载仓库后，双击 [`snake-game/index.html`](snake-game/index.html) 打开离线版本，点击开始，方向键控制。勾选经典模式可体验普通贪吃蛇。

开发工具：ChatGPT（代码生成）；测试环境：Node.js 22.16.0。基础玩法测试不需要额外 npm 依赖。

```sh
cd Task01/snake-game
node --test core.test.cjs
```

如需尝试真实 AI，复制 `.env.example` 为 `.env`，根据服务商官方文档填写文本和图像模型的 URL、密钥与模型名（可能产生费用），再运行：

```sh
node --env-file=.env server.mjs
```

访问 `http://127.0.0.1:8765`。仅供本地学习，不宜直接部署到公网；真实模型兼容性未测试。不要上传 `.env`。

## 3. 实现思路

项目分两步实现：先完成移动、进食、计分、碰撞和重开；再增加文字收集、八词触发、诗画生成以及模型接口。将游戏规则与界面交互分开，便于单独检查和修改。

关键代码：

| 文件 | 作用 |
|---|---|
| `index.html` | 页面结构 |
| `style.css` | 界面样式 |
| `core.js` | 棋盘状态、转向、进食、碰撞与分数 |
| `app.js` | 画布渲染、玩家输入、诗画流程 |
| `server.mjs` | 服务端模型接口与静态资源 |
| `core.test.cjs` | 基础规则单元测试 |

## 4. 自动化测试与问题记录

- Node 单元测试 9/9 通过，覆盖移动、转向与反向限制、进食增长及计分、撞墙、撞自身、尾格边界、暂停、重置和满棋盘食物处理。见 [测试输出](test-results.txt)。
- `node --check` 对 `app.js` 和 `server.mjs` 的语法检查成功。
- 本地 HTTP 服务返回 `{"live":false}`，未配置模型的生成请求返回错误提示；没有调用任何真实模型。
- Chromium 自动化访问本地网页及本地文件时均被运行环境策略拦截（`ERR_BLOCKED_BY_ADMINISTRATOR`），因此浏览器交互和八词触发流程尚未完成测试。
- 在测试中专门覆盖了移动进入即将腾空的尾格这一边界：非进食时应允许，而不是错误地判定自撞。

## 5. 学习思考

之前做过「足迹地球」App，也有过使用 AI 开发应用的经验。相比单纯通过自然语言做出一个可以展示的页面，我更关心的是应用背后的代码逻辑，以及如何判断实现的功能是否符合预期。

这次的贪吃蛇虽然只是一个小项目，但涉及游戏状态、键盘交互、碰撞判断、计分和模型接口，适合用来理解程序的基本组成。尤其是诗画生成环节，使用固定规则拼接文字和实际调用大模型是两种不同的实现方式。

接下来希望进一步补足编程和软件工程基础，逐步建立阅读代码、定位问题、测试功能和迭代应用的能力。
