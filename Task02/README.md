## 一、学习要点

### 1. IDE 与 AI IDE

普通 IDE 提供文件编辑、语法提示、终端、调试和版本管理等基础工具。AI IDE 在此基础上引入模型与 Agent，可以依据自然语言理解项目、创建或修改多个文件、协助运行和排查错误。

学习时比起纠结工具排名，更值得关注开发的基本链路：项目目录 → 编辑器 → 终端启动 → 浏览器查看 → 报错定位 → 代码变更检查 → Git 保存。

### 2. 开发环境中常见的几个概念

| 概念 | 我的理解 |
|---|---|
| 项目根目录 | 一次开发工作的文件范围，先确认目录才能避免误改其他项目 |
| 终端 Terminal | 启动项目、检查环境和运行测试的地方 |
| 依赖 Dependency | 项目运行需要的外部代码或工具，不等于系统自带 |
| 本地服务 localhost | 在自己电脑上启动的程序，通过端口供浏览器访问 |
| Diff / Revert | 查看一次修改到底改变了什么，并在不满意时撤回 |
| Git Commit | 保存可追溯的代码版本，便于比较或回滚 |

### 3. AI IDE 的使用方式

本章官方以 **Trae** 为示例，也介绍了 Cursor、VS Code 等工具。这里选择 **Cursor** 作为本地实践工具，基本流程可以迁移。阅读教程不等于已完成本地环境操作，相关运行结果以本机验证为准。

## 二、2048 游戏练习

相较 Task01 的贪吃蛇，这次选择 2048：需要处理二维棋盘、同数合并、一次移动只合并一次、得分、无可移动位置和撤销历史等逻辑。

项目文件在 [2048](./2048/)：

- `index.html`：页面结构、计分和按钮。
- `style.css`：视觉布局和移动端适配。
- `game.js`：合并、移动、得分、生成数字及结束判断。
- `main.js`：键盘、触屏输入与界面刷新。
- `game.test.cjs`：游戏逻辑测试用例。

本次分成两步迭代目标：

1. **基础玩法**：4×4 棋盘、方向键移动、相同数字合并、计分和重新开始。
2. **交互完善**：加入撤销一步、最高分记录、WASD 操作、触屏滑动及移动端布局。

本仓库提供可直接导入 IDE 的完整源代码。需在本地 IDE 打开、实际操作并记录运行结果，才能验证本章的本地开发流程。

### 在 Cursor 中实践

1. 下载或 Clone 本仓库，在 Cursor 里用 **Open Folder** 打开 `Task02/2048`。
2. 打开内置终端，执行 `python -m http.server 8000`（已经安装 Python 时），或使用 IDE 的本地预览能力。
3. 浏览器访问 `http://localhost:8000`，点击开始，试玩方向移动、合并、得分、撤销、重开。
4. 可以选中 `game.js`，让 AI 解释 `slide()` 与 `move()` 的区别，再尝试修改一个局部规则。
5. 有 Node.js 时，在项目目录执行 `node --test game.test.cjs` 检查基础逻辑。

> 双击打开 `index.html` 也可作为静态页面进行试玩；但它不等于已经练习了启动本地开发服务器。

### 较容易理解错的代码逻辑

`slide([2,2,2,2])` 的结果应是 `[4,4,0,0]`，而非 `[8,0,0,0]`。这是因为 **一次移动中，每个数字块只参与一次合并**。合并后还需生成一个新数字，而无效方向不能额外生成方块。

### 测试记录

游戏核心逻辑在 JavaScript 执行环境进行 **8 项规则用例检查，全部通过**（包括合并、得分、撤销、无效操作和终局判断）。仓库中提供了对应 Node 测试脚本，方便本地复核。

浏览器实际试玩、Cursor 本地运行及界面截图，以本机操作为准，不将静态代码检查视为完整的游戏运行验收。

## 三、学习思考

此前已经借助 AI 完成过「足迹地球」等应用，本章的 IDE 界面和工具介绍不算完全陌生。比较有价值的是把一次开发任务拆成具体的操作环节：在哪个目录工作、AI 改了哪些文件、如何启动项目、出错后检查哪里、什么时候提交版本。

2048 的合并规则也提醒我，功能看起来简单，并不代表实现时没有边界条件。后续希望更多练习阅读代码、理解状态变化和检查 AI 修改，而不是只看最终界面是否做出来。
